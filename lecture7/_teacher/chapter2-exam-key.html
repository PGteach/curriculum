Section B — marking scheme
25What is meant by a security incident? Give two typical examples.
2-3 — Ministry assessments, lesson 2-3, period 1, essay 1; Book p.49
[2 marks]

Model answer. A security incident is a situation in which actual damage occurs due to an information security problem. Examples: an information leak (personal or confidential information leaked to the outside), data tampering, or a service outage caused by attacks on the server.

Award a mark for each:

  • Correct definition: actual damage from an information security problem (1)
  • Two of the three typical examples (1)
26Why is placing a public web server in a DMZ safer than placing it directly inside the organization's internal network?
2-2 — Ministry assessments, lesson 2-2, period 1 home tasks, essay 2; Book p.43 Pause & Think
[3 marks]

Model answer. The public web server is the part most exposed to attack from the Internet. In a DMZ it is kept separate from the internal network, so if it is attacked the attacker still cannot reach the internal network and its confidential data. Inside the internal network, a hacked public server would give the attacker a way straight in.

Award a mark for each:

  • The public server is the most exposed to attack (1)
  • The DMZ keeps it separate from the internal network (1)
  • So an attack on it does not reach the internal network / its data (1)
27Explain how using a second, independent factor (such as an authenticator app or an SMS code) prevents an account being broken into, even if the main password is leaked.
2-1 — Ministry assessments, lesson 2-1, weekly model B, essay 4; Book p.36 Pause & Think
[3 marks]

Model answer. The password is one factor: knowledge. The second factor is from a different category: possession — a code sent to the owner's phone or shown in their app. An attacker who has the leaked password still does not have the owner's device, so cannot get the code, and the login is blocked.

Award a mark for each:

  • The password is only one factor, knowledge (1)
  • The second factor is a different category, possession, which the attacker does not have (1)
  • So knowing the password alone is not enough to log in (1)

28Compare traditional security with zero trust, and explain why traditional designs alone are no longer enough today.
2-2 — Ministry assessments, lesson 2-2, weekly model A, essay 4; Book p.43
[4 marks]

Model answer. Traditional security protects a perimeter, on the idea that inside the organization's network is safe and outside is dangerous, so users inside are trusted once they are in. Zero trust trusts no communication automatically, even from inside the network, and verifies every access — identity, permissions and context — every time. Traditional designs alone are no longer enough because cloud services and remote work have blurred the line between inside and outside, so protecting only the perimeter leaves gaps.

Award a mark for each:

  • Traditional: protects the perimeter; inside is assumed safe (1)
  • Zero trust: no automatic trust, even inside (1)
  • Zero trust verifies every access (identity, permissions, context) (1)
  • Why traditional is not enough: cloud services and remote work blurred inside and outside (1)
29Explain why the six stages of incident response must be carried out in order, using recovery and eradication as an example. Refer to what happens if the cause is not removed.
2-3 — Book p.51 — Exam-style question [6]; Ministry assessments, lesson 2-3, weekly model A, essay 4
[6 marks]

Model answer. Each stage depends on the one before it. Containment comes first, to stop the damage spreading; eradication then removes the cause, such as the malware; only after that does recovery return the systems to normal. If recovery is done before eradication, the systems are restored while the cause is still there, so the same incident can happen again and the work has to be repeated. Following the order keeps the damage small and stops the incident returning; in practice, if recovery reveals traces of the threat, the team goes back to containment or eradication.

Award a mark for each:

  • Containment first stops the damage spreading (1)
  • Eradication removes the cause, e.g. the malware (1)
  • Recovery returns systems to normal only after that (1)
  • If recovery comes before eradication, the cause is still there (1)
  • So the same incident can happen again (1)
  • Conclusion: order keeps damage small / the team may step back a stage (1)

30Explain why HTTPS uses public-key cryptography to share the key but common-key cryptography to exchange the data. Refer to security and speed.
2-1 — Book p.37 — Exam-style question [6]; Ministry assessments, lesson 2-1, weekly model B, essay 2
[6 marks]

Model answer. HTTPS needs the same common key on both sides, but sending it openly would let an eavesdropper copy it. Public-key cryptography solves this: the browser locks the common key with the server's public key, and only the server's private key can unlock it, so the key is shared safely. But public-key cryptography is slow, so exchanging all the data with it would make the connection slow. Common-key cryptography is fast, so once the key is shared, the data is exchanged with it. This division of roles gives both security and speed.

Award a mark for each:

  • Both sides need the same common key, and sharing it openly is not safe (1)
  • Public-key cryptography shares the key safely: public key locks, private key unlocks (1)
  • Public-key cryptography is slow for large amounts of data (1)
  • Common-key cryptography exchanges large amounts of data quickly (1)
  • So public-key is used only to share the key, common-key for the data (1)
  • Result: security and speed together (1)
