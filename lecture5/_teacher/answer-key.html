3Explain why HTTPS uses public-key cryptography to share the key but common-key cryptography to exchange the data. Refer to security and speed.
p.37 — Exam-style question [6]
[6 marks]

Model answer. HTTPS needs a common key on both sides, but sending it openly would let an eavesdropper copy it. Public-key cryptography solves this: the browser locks the common key with the server's public key, and only the server's private key can unlock it, so the key is shared safely. But public-key cryptography is slow, so exchanging all the data with it would make communication slow. Common-key cryptography is fast, so once the key is shared, all the data is exchanged with it. This division of roles gives both security and speed.

The answer must cover:

  • Both sides need the same common key, and sharing it openly is not safe (1)
  • Public-key cryptography shares the key safely — public key locks, private key unlocks (1)
  • Public-key cryptography is slow for large amounts of data (1)
  • Common-key cryptography exchanges large amounts of data quickly (1)
  • So public-key is used only to share the key, common-key for the data (1)
  • Result: security and speed together (1)

4Explain why using public-key cryptography for all the data exchanged would be slow, and how TLS solves this problem by using session keys.
Ministry assessments, form B — essay 2
[4 marks]

Model answer. Public-key cryptography is slow, so using it for every piece of data exchanged would slow the connection. In the TLS handshake, public-key mechanisms are used only to authenticate and to agree session keys safely. A session key is a common (symmetric) key for that connection, and after the handshake the session data is protected with it, which is fast and efficient.

The answer must cover:

  • Public-key cryptography is slow for large amounts of data (1)
  • Public-key mechanisms are used only in the handshake: authentication and agreeing the keys (1)
  • Session keys are common (symmetric) keys for the connection (1)
  • The session data is then protected by symmetric encryption, quickly (1)

11Explain briefly how the different security technologies (encryption, certificates, two-factor authentication) are combined when a purchase is completed in an online shop.
p.36 — Point 3(2); Ministry assessments, period 3 — home tasks
[4 marks]

Model answer. When you open the shop, HTTPS starts and encryption stops third parties reading the content. The browser checks the digital certificate to confirm it is the genuine shop. At login, two-factor authentication (password plus an SMS code) blocks unauthorized logins. When the order is sent, a digital signature can be used so that tampering is detected.

The answer must cover:

  • Encryption / HTTPS: content cannot be read by third parties (1)
  • Digital certificate: confirms the genuine shop (1)
  • Two-factor authentication at login: blocks unauthorized logins (1)
  • Digital signature on the order, or: together they address several threats at once (1)
12Discuss why advanced security measures such as TLS and two-factor authentication do not mean that protection is absolute, or that the website's content can be fully trusted.
Ministry assessments, form C — essay 4; Arabic book p.32 intro
[4 marks]

Model answer. TLS protects the connection: the data cannot be read or changed on the way, and the certificate shows the server matches the site's name. It says nothing about whether what the site says or sells is honest. Two-factor authentication lowers the chance of unauthorized login but does not remove it. Each measure reduces risk rather than removing it, which is why services layer several and none is assumed to stop a threat absolutely.

The answer must cover:

  • TLS / the padlock protects the connection, not the honesty of the content (1)
  • The certificate confirms the site matches its name, not that the site is trustworthy (1)
  • 2FA reduces the chance of unauthorized login; it does not remove it (1)
  • Each measure reduces risk; none is absolute — so they are layered (1)

16Discuss: “Secure online communication and services depend on combining encryption and authentication, not on a single technology.” Show the role of each technology in the combination.
p.34 Key Fact; Ministry assessments, form A — essay 4
[6 marks]

Model answer. Each technology covers a different threat. Encryption prevents the content being read by third parties. A digital certificate verifies that the other side is genuine, stopping a fake site. A digital signature detects tampering and impersonation of the sender, and gives non-repudiation. Multi-factor authentication prevents unauthorized logins even if a password leaks. No single one covers all four threats, so services combine them, and then eavesdropping, tampering, impersonation and unauthorized login are addressed at the same time.

The answer must cover:

  • Encryption — stops eavesdropping (1)
  • Digital certificate — confirms the partner, stops a fake site (1)
  • Digital signature — detects tampering; non-repudiation (1)
  • Multi-factor authentication — stops unauthorized login (1)
  • No single technology covers every threat (1)
  • Combined, many threats are handled at the same time (1)
