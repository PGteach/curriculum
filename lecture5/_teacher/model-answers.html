2Answer the following questions.

1. Why common-key rather than public-key for the data?

Public-key cryptography is slow for large amounts of data, while common-key cryptography exchanges data quickly. The common key itself was already shared safely using public-key cryptography, so using it for the data is both fast and safe.

المتماثل سريع، والمفتاح بتاعه اتشارك بأمان قبل كده بالمفتاح العام.

2. Three steps, in order

(1) The server sends its digital certificate, and the browser checks it: is it valid, does it lead to a trusted authority, does it match the site's name? (2) The two sides agree the common key — the session key — using public-key mechanisms. (3) The data is exchanged, protected with common-key (symmetric) encryption.

الشهادة ← مفاتيح الجلسة ← تبادل البيانات بالتشفير المتماثل.

3Explain why HTTPS uses public-key cryptography to share the key but common-key cryptography to exchange the data. Refer to security and speed.

HTTPS needs the same common key on both sides, but sending that key openly would let an eavesdropper copy it. Public-key cryptography solves this: the browser locks the common key with the server's public key, and only the server's private key can unlock it, so the key is shared safely. However, public-key cryptography is slow, so exchanging all the data with it would make the connection slow. Common-key cryptography is fast, so once the key has been shared, all the data is exchanged with it. This division of roles gives HTTPS both security and speed.

الفكرة في ست نقط: لازم مفتاح مشترك ← إرساله مكشوف مش آمن ← المفتاح العام بيشاركه بأمان ← بس العام بطيء ← المتماثل سريع للبيانات ← النتيجة أمان وسرعة.

4Explain why using public-key cryptography for all the data exchanged would be slow, and how TLS solves this problem by using session keys.

Public-key cryptography is slow, so using it for every piece of data would slow the whole connection down. TLS uses public-key mechanisms only during the handshake, to check the server and to agree session keys safely. A session key is a common (symmetric) key for that one connection. After the handshake, all the session data is protected with symmetric encryption using the session key, which is fast and efficient.

TLS بيستخدم المفتاح العام في المصافحة بس، وبعد كده مفاتيح الجلسة المتماثلة بتحمي البيانات بسرعة.

5Answer the following questions.

1. The role of the certificate and public-key mechanisms when TLS starts

The server sends its digital certificate, and the browser checks that it is valid, leads back to a trusted certificate authority and matches the site's name — so the browser knows it is talking to the real server. Public-key mechanisms then let the two sides agree session keys safely.

الشهادة بتثبت إن الخادم حقيقي، وآليات المفتاح العام بتخلي الطرفين يتفقوا على مفاتيح الجلسة بأمان.

2. Digital signature compared with digital certificate

A digital certificate answers: is the other side genuine? It verifies that the communication partner is authentic and stops a fake website. A digital signature answers: was this data altered, and who sent it? It detects tampering and impersonation of the sender, and gives non-repudiation — the sender cannot deny having sent it.

الشهادة عن الطرف التاني، والتوقيع عن البيانات نفسها ومين بعتها.

7Answer the following questions.

1. What 2FA means, and how a second factor reduces risk

Two-factor authentication uses two independent factors from two different categories to prove who you are. If the password is leaked, the attacker still needs the second factor — for example a code sent to the owner's phone — so knowing the password alone is not enough to log in.

لو الباسورد اتسرب، اللي هاجم لسه محتاج العامل التاني اللي مش معاه.

2. 2FA compared with MFA

2FA uses exactly two factors, from two different categories. MFA uses two or more independent factors from different categories (knowledge, possession, biometric). So every 2FA is MFA, but not every MFA is 2FA.

2FA = اتنين بالظبط، MFA = اتنين أو أكتر — والاتنين من فئات مختلفة.

9If a password is leaked, why can a second factor sent to a phone still keep the account safe?

A password is only one factor: knowledge. The second factor is a different category: possession. The code goes to the owner's phone, which the attacker does not have, so even with the leaked password the attacker cannot complete the login.

11Explain briefly how the different security technologies (encryption, certificates, two-factor authentication) are combined when a purchase is completed in an online shop.

When you open the shop, HTTPS begins, and encryption stops third parties from reading what you send. The browser checks the shop's digital certificate to confirm it is the genuine shop and not a fake one. When you log in, two-factor authentication — a password plus an SMS code — blocks unauthorized logins. When you send the order, a digital signature can be used so that any tampering is detected. Together they deal with several threats at the same time.

التشفير ← الشهادة ← المصادقة الثنائية ← التوقيع: كل خطوة بتقف قصاد تهديد مختلف.

12Discuss why advanced security measures such as TLS and two-factor authentication do not mean that protection is absolute, or that the website's content can be fully trusted.

TLS protects the connection: the data cannot be read or changed on the way, and the certificate shows that the server matches the site's name. But it says nothing about whether the site itself is honest, so its content is not automatically trustworthy. Two-factor authentication lowers the chance of an unauthorized login, but it does not remove it completely. Each measure reduces risk rather than removing it, which is why services layer several technologies and never assume that any one of them is absolute.

القفل بيحمي الاتصال، مش بيضمن إن الموقع نفسه أمين. وكل تقنية بتقلل الخطر، مفيش واحدة بتلغيه.

13A small online shop wants to secure both customer login and payment. Name two security technologies it should use and say where each one helps, then identify one threat that could still remain.

One possible answer. For customer login, the shop should use multi-factor authentication, such as a password plus an SMS code, so that a leaked password alone cannot open an account. For payment, it should use HTTPS: encryption stops the card details being read on the way, and the digital certificate shows customers they are on the real shop. One threat could still remain: a customer could be tricked into typing their password and code into a fake page, because no technology is absolute.

ده مثال لإجابة واحدة صح — أي تقنيتين مناسبتين مع مكانهم وتهديد باقي بيتقبلوا.

14Think as an engineer. A school's online portal lets students check grades and pay fees. Password only, or a password plus a one-time password sent to the phone? For a student, the school, and a student with no smartphone, note one benefit and one drawback of a second factor. Then recommend one login method and give two reasons.

One possible answer. A student: a second factor keeps their grades and fee payments safe, but it takes a little longer to log in. The school: it protects student records and payments, but it must support the extra step. A student with no smartphone cannot receive the code, so the school needs another way, such as a code by SMS to a basic phone or a card. Recommendation: a password plus a one-time password, because a leaked password alone can no longer open an account, and the account holds money and private records — with another option for students without a smartphone.

مثال لإجابة: لازم فايدة وعيب لكل طرف، وبعدين قرار واحد بسببين.

15Challenge: suggest one extra security measure an online shop could add, and one threat it would still not remove.

One possible answer. Extra measure: a digital signature on each order, so that any change to an order on the way is detected. A threat it would still not remove: a customer whose password and code are stolen by a fake site — the signature protects the order, not the login.

أي إجراء مناسب مع تهديد فعلاً هيفضل موجود.

16Discuss: “Secure online communication and services depend on combining encryption and authentication, not on a single technology.” Show the role of each technology in the combination.

Each technology deals with a different threat. Encryption prevents communication content from being read by third parties. A digital certificate verifies that the other side is genuine, so a fake site is caught. A digital signature detects tampering and impersonation of the sender, and gives non-repudiation. Multi-factor authentication prevents unauthorized logins, even when a password leaks. No single technology covers all four threats, so services combine them, and eavesdropping, tampering, impersonation and unauthorized login are all dealt with at the same time.

أربع تقنيات لأربع تهديدات — ومفيش واحدة لوحدها بتغطيهم كلهم.
