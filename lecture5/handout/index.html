Every login hides three jobs

Every time you log in to a bank app, buy something online, or open a website with a padlock in the address bar, hidden technologies keep your information safe: messages are scrambled so no one else can read them, the website proves that it is genuine, and your identity is checked before you are let in. Without them, passwords could be stolen and private data read.

فيه كذا تقنية بتحمي الاتصال: TLS بيشفّر البيانات، والمتصفح بيتأكد من شهادة الموقع، والخدمة بتتأكد من هويتك — بس ده مش معناه إن محتوى الموقع موثوق أو إن الحماية مطلقة.

Today’s question. How do cryptographic technologies and authentication work together to keep online communication and services secure?

السؤال الرئيسي: إزاي تقنيات التشفير والمصادقة بتشتغل مع بعض عشان تحافظ على أمان الاتصال والخدمات عبر الإنترنت؟

Part 1 · Encryption

Encryption

Scrambles a message so that only someone with the right key can read it — it keeps content private.

التشفير بيحافظ على خصوصية المحتوى: محدش يقدر يقرا الرسالة غير اللي معاه المفتاح الصح.

One key, or a pair of keys

Common-key (symmetric-key) cryptography exchanges data quickly; public-key cryptography shares a key safely.

التشفير المتماثل بيبادل البيانات بسرعة، والتشفير بالمفتاح العام بيشارك المفتاح بأمان.

Which key does what

Locks / signs withUnlocks / verifies with
Encryption (public-key)the receiver’s public keythe receiver’s private key
Digital signaturethe sender’s private keythe sender’s public key

Part 2 · HTTPS and the TLS handshake

HTTPS (HTTP Secure)

A communication protocol that adds TLS encryption to HTTP. It provides encryption, detection of tampering and verification of the communication partner, protecting users from eavesdropping, tampering and impersonation. Setting up the secure connection is the TLS handshake.

HTTPS: بروتوكول HTTP منقول عبر اتصال TLS مؤمَّن. وخطوات إنشاء الاتصال الآمن اسمها مصافحة TLS.

Three stages, two kinds of key

StageWhat happensMethod
1 ConnectionThe server sends a digital certificate and a public key; the browser verifies the server through a certificate authority (CA).Public-key
2 Key exchangeThe browser creates a common key, encrypts it with the server’s public key and sends it; the server decrypts it with its private key.Public-key
3 DataData is encrypted and exchanged using the shared common key.Common-key
Prepared by: Mr. Eissa Islam

Why not public-key for everything? Public-key cryptography shares keys safely but is slow; common-key cryptography exchanges large amounts of data quickly. This division of roles gives both security and speed. The common key for one connection is a session key; current versions of TLS agree on it by Diffie-Hellman key agreement.

آليات المفتاح العام للمصادقة والاتفاق الآمن على مفاتيح الجلسة، والتشفير المتماثل لحماية بيانات الجلسة بسرعة.

Who vouches for the website?

Digital certificate

Verifies that the communication partner is authentic. A certificate authority (CA) vouches that a site is genuine.

الشهادة الرقمية بتساعد المتصفح يتأكد من هوية الخادم وارتباط الشهادة باسم النطاق اللي بيتصل بيه.

During the handshake the browser checks that the certificate is valid, that it leads back to an authority it trusts (the chain of trust), and that it matches the name of the site.

المتصفح بيتأكد من صلاحيتها وسلسلة الثقة وملاءمتها لاسم الموقع.

Proving who sent it, and that it was not changed

Digital signature

Detects data tampering or impersonation of the sender, and makes it impossible for the sender to deny having sent the data afterward: non-repudiation.

التوقيع الرقمي بيكشف التلاعب وانتحال الشخصية، وبيوفّر دليل بيدعم عدم التنصل.

Digital certificateDigital signature
Is the other side genuine?Was this data altered, and who sent it?
Stops a fake websiteDetects tampering; gives non-repudiation

The padlock. It shows the connection is encrypted and the site matches its certificate. It does not mean the content can be trusted completely, or that protection is absolute.

القفل مش معناه إن محتوى الموقع موثوق أو إن الحماية مطلقة.

Part 3 · Authentication

المعرفة (كلمة مرور، سؤال سري) · الحيازة (كلمة مرور لمرة واحدة، SMS، بطاقة ذكية) · السمات الحيوية (بصمة، وجه).

Multi-factor authentication (MFA)

Combining two or more of the three factors: knowledge, possession, biometric. With one factor, breaking it lets an attacker in; with several, even if one is broken, another can still prevent access.

لو عامل واحد واتكسر، اللي هاجم يدخل. لكن عامل تاني مستقل بيقلل احتمال الدخول غير المصرح به.

Two-factor authentication (2FA)Multi-factor authentication (MFA)
Exactly two independent factors, from two different categoriesTwo or more independent factors, from different categories
ServiceAuthentication usedFactors
Online bankingPassword + one-time passwordknowledge + possession
SNS loginPassword + SMS authenticationknowledge + possession
Online shoppingPassword + one-time code from 3-D Secureknowledge + possession
Company laptop loginSmart card + fingerprint authenticationpossession + biometric

Exam warning. Two passwords, or a password and a secret question, are not multi-factor: both are knowledge, the same factor twice (two-step authentication).

كلمتين مرور مش مصادقة ثنائية — الاتنين من عامل المعرفة.

In a new context

A small online shop wants to secure both customer login and payment. Name two security technologies it should use and say where each one helps, then identify one threat that could still remain.

سمّي تقنيتين أمان وبيّن كل واحدة بتساعد فين، وحدد تهديد واحد ممكن يفضل موجود.

Key takeaway · share the key safely, move the data quickly

HTTPS uses public-key cryptography to share a key safely and common-key cryptography to move data quickly. Services stay safe by layering encryption, certificates, signatures and multi-factor authentication.

افتكر: آليات المفتاح العام للمصادقة ومفاتيح الجلسة، والتشفير المتماثل لبيانات الجلسة. والخدمات بتفضل آمنة بتكديس التشفير والشهادات والتوقيعات والمصادقة الثنائية.

Lesson question — answered

HTTPS combines public-key cryptography, to share a key safely, with common-key cryptography, to exchange data quickly, so communication is both secure and fast. Services stay safe by combining encryption (hides content), digital certificates (prove a site is genuine), digital signatures (detect tampering) and multi-factor authentication (blocks unauthorized logins), so many threats are addressed at the same time.
