Part 1 · The roles of HTML, CSS, and JavaScript

A page is built like a building

These three technologies each have independent roles, and a web page is created using them in combination.

التقنيات دي بتأدي أدوار مختلفة: HTML بيبني الهيكل، و CSS بيضيف التنسيق، و JS بيضيف السلوك التفاعلي.

1 · Who does what

Structure, appearance, behavior

TechnologyRoleAnalogy
HTMLDefines the structure (skeleton): headings, paragraphs, images, linksThe frame of a building
CSSSpecifies the appearance: colours, layout, size, fontsThe interior and exterior
JavaScriptAdds behavior and interactivity: responds when buttons are pressed, updates part of the screenThe electrical and plumbing systems

The Arabic book adds: a page does not have to use all three. It can be HTML alone, or HTML with CSS and JavaScript, depending on what it needs to do.

HTML بيحدد بنية الصفحة، و CSS بيحدد مظهرها، و JavaScript بيضيف السلوك والتفاعلية. والصفحة ممكن تستخدم HTML لوحده، أو HTML مع CSS و JavaScript حسب الوظايف اللي محتاجاها.

Part 2 · Semantic HTML

Tags that say what a part is

Semantic HTML — describing each part of a page with element names (tags) that show their meaning.

HTML الدلالي: استخدام عناصر بتوضح وظيفة أجزاء الصفحة، زي <header> في أعلى الصفحة، و <nav> للتنقل، و <main> للمحتوى الرئيسي، و <footer> في أسفل الصفحة.

2 · Why use it?

Two benefits

BenefitWhat it means
AccessibilityScreen-reader software can understand the page’s structure, so information reaches users with visual impairments more easily.
SEO (search engine optimization)Search engines can understand the content more easily, so it is more likely to be shown properly in results.

The Arabic book is careful: semantic HTML helps search engines, but it does not guarantee a higher ranking — and accessibility needs other good practices too.

  • Pause & think: why does a screen reader understand a page better with <header>, <nav> and <main> than with plain boxes? — the tag names the part, so it can say “navigation” or “main content” and let the user jump there.

فوايد HTML الدلالي: إمكانية الوصول — بيساعد قارئ الشاشة يفهم بنية الصفحة ويتنقل فيها، مع الحاجة لممارسات وصول تانية. وفهم محركات البحث للمحتوى — ممكن يساعدها، لكنه مش بيضمن ترتيب أعلى.

2 · The same page, two ways

Plain boxes or meaningful tags?

Plain boxes

<div>Science Club</div> <div>Home | Events</div> <div>Robot day ...</div> <div>© 2026</div>

Works — but nothing says which part is which.

Semantic HTML

<header>Science Club</header> <nav>Home | Events</nav> <main>Robot day ...</main> <footer>© 2026</footer>

Same look — and every part is named.

الاتنين ممكن يبانوا نفس الشكل، بس في التاني كل جزء ليه اسم بيوضح وظيفته.

3 · Mobile first

Why it matters now

Many people use the web on their phones, so developers think about small screens from the very start of the design. This is called mobile-first.

  • Why is responsive design needed? — because websites are accessed from many devices: PCs, smartphones and tablets.
  • Does it make the server faster? — no: it is about the layout on the screen.
  • “Mobile-first” means designing first for… — small screens such as phones.

ناس كتير بتستخدم الويب من الموبايل، عشان كده المطورين بيراعوا الشاشات الصغيرة من بداية التصميم. وده اسمه نهج الأولوية للجوال.

Exam warning

True or false?

  • Using semantic HTML necessarily makes a page display faster. — false: its benefits are accessibility and SEO.
  • A framework is a language for defining the structure of a page. — false: that is HTML.
  • Responsive design means the page works only on computers. — false: it adapts to every screen.
  • Next.js is built on React. — true.

خلّي بالك: HTML الدلالي مش بيسرّع الصفحة بالضرورة. إطار العمل مش لغة لبنية الصفحة. التصميم المتجاوب مش للكمبيوتر بس. و Next.js مبني على React — صح.
